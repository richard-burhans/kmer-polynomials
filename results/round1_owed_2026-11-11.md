## 1. Independent x and λ (adjudication L1 F1)

- **The new rule.** `hash/kp7seed.h` supplies two sources, one for x and one for λ.
  - With no seed, a parameter comes from OS randomness (`getrandom`). That is the default.
  - With a seed, it comes from a deterministic splitmix64 stream. The x and λ streams carry different domain tags.
  - Each field part is drawn by masking to the Mersenne width and rejecting out-of-range values, so there is no
    modular bias.
  - x is uniform on the nonzero elements and λ on the whole field.
- **Where it applies.** `kp7e_init`, `kp7_init` and `kp7m31_init` now take `(seed_x, seed_lam)`. The `*_init_seeds`
  variants take pointers, and NULL means OS randomness. kp7pack and the `ideas/` spaced-seed code inherit these
  parameters. The Python ports follow suit: `params(k, seed_x=None, seed_lam=None)`. `recon/kp10.py` takes
  `--seed-x/--seed-lam` and records the x and λ it drew.
- **Deterministic mode, and its limit.** Seeded runs reproduce exactly, but a 64-bit seed cannot fill an F_{q²} element
  uniformly. Only the OS mode meets the bound's premise for the F_{q²} hashes.
- **Tests and mutants.**
  - New `test_seeds` checks in three C suites and in `tests/test_seeds.py`.
  - Three new mutants (`*_MUTATE_SEED`) restore the old one-stream derivation. All three are killed.
  - `tests/run_all.sh` at 8c34af9 shows every suite passing and all 21 mutants killed (`results/tests_independent_seeds_2026-11-11.txt`, last line).
- **Golden values.** No test pinned a hash value, so none changed.
- **Exhaustive check.** The k = 7/8 check rerun with separate seeds gives the same counts as before
  (`results/kp7_symmetric_check_2026-11-11.txt`).

## 3. Experiments for the reframed paper (Cannbio-2 vs Cannbio-2_draft)

**Pipeline.**
- `hash/kp7e_stream.c` hashes every k-mer in the orientation it is written, straight from the bases. It does no
  packing and works for any k.
- `recon/aswritten.py` keeps the distinct values in 64 value-range partitions.
  - In the sketch, the element is the value itself. The bucket key is the top bits of the value, and nothing else is
    hashed.
  - Each run is verified against the exact difference of the two value sets, then against independent truths on k-mers.
- `recon/run_aswritten_pair.sh` drives the whole run.
- Settings: seeds x 0x5eed, λ 0x1a3d; m = 64 power sums plus c = 2 check sums per bucket; 8 bytes per entry.

**Notes.**
- **(a) The canonical run's outcome holds without canonicalization.** The as-written S run has the same size, rounds and
  recovery as the canonical-code run in `results/kp10_vs_shibuya_2026-11-11.md`.
  - Its value sets have exactly the canonical class counts, 442,151,894 and 442,159,825, so S had no collision among
    the classes.
  - Buckets keyed on S did not upset decoding: there were no splits, and recovery matched three independent truths.
- **(a) The control.** Orientation alone turns 7,931 differences into 398,217,248 for a strand-specific hash, about
  50,000 times as many. Even the distinct-value counts swell, because both strands of a sequence occur across the two
  assemblies.
  - A sketch of the same size decodes nothing. Its 137,216 bytes are spent, and every bucket overflows.
  - Finishing that reconciliation is a **projection, not measured.** It would need about 2²⁴ buckets to bring the
    expected difference per bucket to m/2 = 32, which is about 9 GB of sketch and 16 more split rounds.
- **(b) Why k = 63.** It is the largest odd k that 128-bit packed codes hold, and the common ceiling for k > 32 tools
  (also the paper Supplement's de Bruijn k). Odd k avoids k-mers that equal their own reverse complement. Above 32, a
  64-bit canonical code no longer exists, and S needs no code at all.
- **(b) Sizing and cost.** The bucket count follows the bits_for rule, which reads the true D, as the earlier KP-10 runs
  did.
  - The 25.7 B/difference reflects 2¹⁰ × 67 entries for 21,382 differences. Each base change touches about twice as
    many k-mers at k = 63 as at k = 31.
- **KMC as the truth.** KMC (bioconda 3.2.4, `recon/kmc_diff.sh`, `-ci1`) was calibrated at k = 31, where it reproduces
  recon/kmerset.py exactly: 442,151,894, 442,159,825 and 7,931 (`D/kmc_k31_summary.json`).

**Wall time.** Single core in numpy, on a host shared with other jobs. Two genomes were built in parallel and three
runs at once, so these times are upper bounds.

| step | k = 31 S | k = 31 F | k = 63 S |
|---|---|---|---|
| build: hash and deduplicate, both genomes in parallel | 1,158 s / 1,235 s | 2,115 s / 2,556 s | 2,543 s / 3,167 s |
| reconcile: sketch, decode and verify | 4,387 s | 3,763 s | 5,279 s |

- Build times come from `D/build_*.json` ("seconds"). Most of the build is deduplication and writing to the bench
  virtiofs. The C hashing itself streams a genome in seconds.
- The reconcile time is dominated by the numpy power sums (|A|·(m + c) field multiplications).

## What did not work, and caveats

- **Stream writes.** Writing all hash values to 64 partition files ran at about 4 MB/s on virtiofs. The builds were
  restarted with in-memory passes, 16 per genome.
- **KMC, first attempts.** KMC was OOM-killed twice at `-m4` on this shared 15 GB host. With `-m2` it ran, but at first
  with `-cs1`, which makes counter-less sets that kmc_tools cannot subtract. The fix is `-cs255` (ad3c1d9).
- **seedrc output.** The first output interleaved ntHash's stderr into a data row. It was regenerated with stderr after
  the table (7aa6e62).
- **run_kompa.py was not rerun.** `prototype/run_kompa.py` now draws x0 and its evaluation points from separate
  generators, but its committed results are from the old draw.
- **One header says "+uncommitted".** The nteq header (`results/nteq_cs10_2026-11-11.txt:2`) carries the flag because an
  unrelated Makefile entry (kp7e_stream) was uncommitted at the time. nteq.cpp itself was committed (18316b0).
